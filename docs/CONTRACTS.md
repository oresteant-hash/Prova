# Internal implementation contracts

Python package `app`, pandas/numpy; FastAPI serves vanilla HTML/JS UI.

## Configuration
`app.models.StrategyConfig` (Pydantic) with defaults: formula='uniform' ('reactive'); top_n=6 (2..6); ma_filter=False; weighting='score' ('equal','inverse_vol'); fallback='C3M.MI' ('IBGX.MI'); universe_mode='complete' ('progressive'); min_assets=10; initial_capital=100000; tax_rate=.26; commission_bps=0; spread_bps=0; rebalance_band=0 (fraction, .005 is 0.5pp); start_date=None; end_date=None. `model_dump()` returns serializable values. Config is saved in config/default.json. Do not alter universe IDs/labels.

## Market data
`app.data.MarketData` dataclass: `adjusted: pd.DataFrame` daily adjusted closing prices, `close: pd.DataFrame` daily tradable closing prices, `dividends: pd.DataFrame` daily cash distributions (zero when none), `metadata: dict`, `source: str`, `updated_at: str`, `warnings: list[str]`. Columns tickers, index naive normalized pd.DatetimeIndex. All frames align, no retroactive padding. Assets have distinct first available dates. Prices are EUR. Include twelve strategy symbols + SWDA.MI, AGGH.MI. Monthly adjusted prices are computed by engine, only complete months until asof (asof default current date). Demo is deterministic synthetic data with clear unverified metadata, never silently substituted for Yahoo.
`load_demo() -> MarketData`; `load_cached() -> MarketData | None`; `refresh_yahoo() -> MarketData` validates symbols/currency/exchange/instrument, retains raw/adjusted/dividends + metadata + yfinance version on disk under ignored data/. Any unavailable/mismatched instruments fail explicitly. `instrument_catalog() -> list[dict]`, instrument fields id,label,name,isin,ticker,exposure,role ('asset'/'benchmark').

## Signals and idealized backtest (agent signal)
`app.engine.monthly_prices(adjusted, asof=None) -> pd.DataFrame` excludes current incomplete month. `compute_signal(monthly, config, at=None) -> dict` returns signal_date YYYY-MM-DD (calendar month end), tradable bool (universe readiness), available_count, eligible_count, selected list[ticker], weights dict[ticker,float] (always total 1 for tradable), rows list[dict] in rank order with id,ticker,label,price,r3,r6,r12,score,ma12,volatility,available,eligible,selected,rank (None when unavailable),reason. Strict consecutive months for 13 prices. Inverse_vol availability includes computable positive sample volatility. Progressive needs config.min_assets available, complete needs all 12; fallback requires valid current price even if score negative. Exact ties by ID.
`run_backtest(data: MarketData, config: StrategyConfig, asof=None) -> dict` idealized monthly strategy and common-period benchmarks, no taxes, costs may separately included if declared. returns JSON-serializable `months`: list dict {date,signal_date,weights,drifted_weights,trades?/turnover,asset_returns,return,equity,benchmark_world_return,benchmark_6040_return,benchmark_world_equity,benchmark_6040_equity}; `signals`: list full signal dict; `metrics`: strategy,world,balanced dict; `current_allocation`: signal from last complete month; `provisional_signal`: separate signal with daily adjusted as latest price in explicit incomplete bucket; `live_performance`: {as_of,return_since_month_end,estimated_equity,complete_months}; `warnings`: list; `period`: {start,end,months}. No synthetic extra monthly performance row. start/end dates limit to full months, make precise period explicit. No look-ahead.
`targets_from_backtest(result) -> pd.DataFrame` root may build from signals by date. `app.analytics.metrics(returns, initial_capital, turnover=None) -> dict` keys cumulative_return,cagr,annualized_volatility,max_drawdown,turnover,total_costs,total_taxes. Annualized volatility sample ddof1, drawdown monthly includes initial value, CAGR uses integer M. Agent signal owns engine.py + test_engine.py and can have local private metrics if analytics not ready.

## Operational accounting (agent accounting)
`app.accounting.simulate_accounting(data: MarketData, targets: pd.DataFrame, config: StrategyConfig, tax_mode='all_sales', end_date=None) -> dict` targets: index signal month-end; columns strategy or benchmark tickers; weights sum1. Trades first available session strictly after signal date; prices from close (never adjusted); distributions per held share, tax_rate withheld, net cash reinvested on next rebalance (explicit). Fractional quantities allowed. sale tax gain based average cost, no loss offsets. tax_mode 'exit_only' taxes capital gains on full exits, partial sells exempt as simplified convention, or 'all_sales'. Monthly target drift respected; band configurable. Costs from capital. No borrowing/negative cash/negative positions. returns `equity`: list {date,value,cash}, `monthly_returns`: list {date,return,equity}, `trades`: list {signal_date,date,ticker,side,quantity,price,gross,cost,realized_gain,tax,average_cost_before,position_before,target_weight}, `distributions`: list {...}, `positions_before`: list {signal_date,date,cash,positions: {ticker:{quantity,price,market_value,average_cost,weight}},target_weights}, `totals`: {costs,taxes,realized_gains,turnover}, `before_liquidation`: value, `after_liquidation`: value, `final_liquidation`: separate trades, `warnings`: list. Operational results cannot be presented as identical to monthly theoretical curve. Benchmarks use same accounting engine, targets annually 60/40 or initial world-only.

## Actual-account performance and proxy analysis (agent analytics)
`app.analytics.metrics(...)` above; `xirr(flows: list[{date,amount}]) -> float` signed external contributions negative, withdrawals/terminal value positive; raise ValueError if invalid/no finite unique supported root.
`account_performance(valuations: list[{date,value,external_flow}]) -> dict` valuations after external flow, flow convention contribution positive into account, subperiod return (value-flow)/previous-1; exact TWR only valuation at each flow, validates chronological and nonnegative values, xirr from initial investment plus flows plus terminal. No trading cashflows classified external. Explicit missing data errors. CSV ingestion API root.
`extend_with_proxies(real: pd.Series, proxy: pd.Series, metadata: dict) -> tuple[pd.Series,dict]` historical only separate analysis; requires source,exposure,currency,hedging,duration,distributions and currency EUR, overlap date anchor and normalized return linkage, no filling unavailable months or using future info in strategy; requires dates externally known, reports assumptions. Agent analytics owns analytics.py, proxies.py, test_analytics.py/test_proxies.py.

## API root contract for UI
GET /api/catalog -> {instruments,defaults,providers}
POST /api/backtest JSON {config:dict,source:'demo'|'yahoo'} -> {source,updated_at,metadata,config,months,signals,metrics,current_allocation,provisional_signal,live_performance,period,warnings,accounting:{standard:...,score:...},accounting_benchmarks:{world:...,balanced:...},comparison:[{name,...metrics,before_liquidation,after_liquidation,costs,taxes}]}. Heavy accounting may only include summary/equity in response; full ledger export persisted last result by analysis id.
GET /api/data/status -> provider/cache status
POST /api/data/refresh -> 202 background job {job_id,status}; GET /api/data/refresh/status?job_id=... -> running/updated/failed; failure explicit and no source substitution.
GET /api/export/{analysis_id} -> zip config/catalog/data/metadata/signals/allocations/monthly/ledgers/positions/metrics plus provenance.
POST /api/account-performance -> valuations input; TWR/XIRR.
POST /api/proxy-analysis -> explicit real/proxy monthly data & metadata; separate analysis, never modify live/cache.
Errors FastAPI JSON {detail:message} with status 400/422/502. UI must use all numbers from returned response and state when synthetic demo. Default launch demo explicitly labeled. Config controls all primary params, date inputs explain full-month semantics, sources separated. Detailed score table/export, current vs provisional vs latest mark, accounting vs idealized, annual benchmarks.
